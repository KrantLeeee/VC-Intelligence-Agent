系统架构

五层架构，一体运转

从飞书消息到分析结论，每一步都有明确的归属和边界。安全数据和 AI 推理在架构层隔离，不是事后补丁。

Layer 1 飞书接入层 — 每人一个专属 Hermes

每位投资经理拥有自己独立的 Hermes Agent 实例。各自有独立记忆、独立技能库、独立操作历史。就像团队里每个人有自己的工作方式，但共享同一套知识库。

Layer 2 安全脱敏层 — 本地执行，原始数据不出内网

在任何数据发往 Claude API 之前，本层将敏感信息替换为代号。这是整套系统的信任边界。越过这条线的，只有代号。

创始人 → PERSON-007
融资金额 → [千万级]
细分赛道 → 泛化行业

外部 AI 服务处于信任边界之外。即使 API 日志被泄露，泄露的也是"COMP-042 做了 X 事"，没有商业价值。代号还原只在本地发生。

核心能力

三大支柱，缺一不可

不是三个独立功能，是一个飞轮：记忆提供历史上下文，干活消耗并产生新上下文，成长把结果沉淀回记忆。

解决什么问题

团队经验不再随人走

现在：新同事入职，前辈积累的项目判断经验无法传递。离职就带走了。类似项目靠记忆找，经常漏掉。

系统化之后：100份历史案例全部向量化，任何人输入一个项目描述，3秒内找到最相似的历史案例，附带当时的判断依据和最终结果。

  • 语义检索：不需要记住关键词，描述项目方向就能找到
  • 相似度分级：高于65%才展示，低于阈值明确告知"无历史参照"
  • 来源标注：每条召回结果附原始文件名，可点击验证
  • 投后结果挂钩：找到的历史案例标注"最终投了/Pass了"
技术实现

可信召回 · 四道防幻觉防线

AI 的最大风险是"发明"一个听起来真实的历史案例。我们用四道机制确保每条召回都是真实的、可追溯的。

  • 向量相似度门槛：低于0.65的结果不展示，而不是强行类比
  • 每条召回附原文片段：AI不能在没有来源的情况下引用历史案例
  • 幻觉扫描：第二次 Claude 调用，专门标出哪些是推断、哪些有依据
  • 分类标注输出：✓有依据 / ⚠推断 / ❌与历史矛盾，投资经理一眼识别
pgvector text-embedding-3-small HNSW 索引 余弦相似度 search_similar_cases()
解决什么问题

重复劳动由机器做，判断交给人

现在：每份BP都要人工阅读、写摘要、想DD问题、查竞品。每份2-4小时，大量时间花在信息整理，不是判断。

系统化之后：上传BP，25分钟内自动完成：结构化摘要、相似案例召回、DD清单、初步分析草稿。人的时间用于创始人访谈和最终决策。

  • BP解析：支持PDF/Word/扫描件，自动提取10个关键字段
  • DD清单生成：结合赛道特点和历史案例，按优先级排序
  • 材料缺口检测：自动标注"BP中未提及但需核查"的信息
  • 飞书推送：报告自动创建到飞书文档并@分析师
技术实现

Hermes 工作流 · 8步自动化管线

从飞书接收文件到分析报告输出，8个步骤全自动串联。每步都有明确的输入输出，任何一步失败都有日志记录。

  • Hermes 飞书 Lark adapter：文件上传自动触发，无需额外操作
  • 脱敏在 Claude API 调用前执行，是代码层面的强制约束
  • 两次 Claude 调用：第一次生成报告，第二次独立做幻觉扫描
  • 代号还原只在最终输出阶段，存库的永远是代号版本
Hermes Agent Lark Adapter pdfminer claude-sonnet Supabase
解决什么问题

投资经验沉淀成可检索的资产

现在：项目归档就结束了。两年后同赛道的新项目来了，当初判断对还是错、漏看了什么，没有人记得，也没有地方查。

系统化之后：每个项目有结果更新（获下轮/增长数据/暴雷）时，自动触发复盘流程，把"当初判断 vs 实际结果"的对比写入知识库。

  • 判断复盘：当初的分析草稿和实际结果对比，识别判断盲区
  • 季度报告：哪类公司判断最准？哪类风险点经常被低估？
  • 经验自动提炼：高价值的复盘结论写入 Hermes 技能库
  • 可审阅：技能库是 Markdown 文件，可直接打开检查和修改
技术实现

Hermes Curator · 技能自动迭代

Hermes 的 Curator 机制：每当 Agent 解决了一个新问题，会把解法写成技能文件存在磁盘上。投资场景下，这意味着新赛道的分析框架会被自动记住。

  • 技能文件可读：不是黑盒的"自动学习"，是可以打开阅读的 Markdown
  • 结果数据触发：飞书多维表格里更新项目状态，自动触发复盘
  • 注意时间尺度：一级市场结果要等2-5年，头一年"成长"来自过程反馈
  • 人工质检：每季度30分钟检查技能库有无错误经验需要纠正

步骤 01 文件接收 ~1 秒 全自动
飞书 Lark Adapter 监听到新附件，下载 PDF，用 pdfminer 提取原始文本。支持 PDF / Word / 扫描件（OCR）。
EVENT: message.file_created file: 极光储能_BP_2024Q4.pdf // 2.3MB action: download → extract_text text_chars: 18,420 // 提取成功
步骤 02 实体识别 + 脱敏 ~30 秒 全自动
脱敏引擎扫描文本，识别公司名、人名、金额，替换为代号。代号由 SHA-256 决定，同一家公司永远是同一个代号。
极光储能科技（杭州）有限公司 → COMP-089 王建明，前宁德时代总监 → PERSON-034，前[能源科技]高管 融资需求 3000 万元 → 融资需求 [千万级] 固态电池 BMS 赛道 → [能源科技] BMS 赛道 // 映射写入 Supabase entity_aliases 表
步骤 03 结构化提取 ~2 分钟 Claude API
脱敏后的文本发给 Claude，提取10个标准字段，返回 JSON。Claude 全程只看到代号，不知道这是哪家公司。
{ "company_alias": "COMP-089", "round": "Pre-A", "industry_broad": "能源科技", "amount_range": "千万级", "business_model": "直销+代理，面向工厂园区", "key_risks": ["技术壁垒可复制性存疑", "3家LOI客户集中度风险"] }
步骤 04 历史案例召回 ~1 分钟 向量检索
用项目摘要生成向量，在 pgvector 索引中检索相似历史案例。只返回相似度 ≥ 65% 的结果，低于阈值明确告知"无历史参照"。
QUERY: "工商业储能初创 BMS算法差异化 Pre-A" MATCH 1: COMP-042 similarity=0.88 来源: 2022_储能_工商业.md outcome=PASSED reason=客户集中度过高 MATCH 2: COMP-061 similarity=0.71 来源: 2023_BMS_算法公司.md outcome=INVESTED A轮估值翻2x
步骤 05 报告 + DD清单 ~5 分钟 Claude API
把结构化数据 + 历史案例 + 赛道DD框架一起发给 Claude，生成完整的初步分析报告和按优先级排序的DD问题清单。
## DD 优先问题清单（按重要性排序） 1. 3家LOI客户的付款进度？是否有独立客户？ // 参照 COMP-042 Pass 原因 2. BMS算法的专利申请状态？核心代码IP保护？ 3. 循环寿命数据是否有第三方测试报告？ 4. 毛利率结构 · 竞业限制 · 股权结构 …（共8条）
步骤 06 幻觉扫描 ~3 分钟 独立核查
第二次独立的 Claude 调用，以"质检员"身份对比报告与历史数据，标出每条结论的可信度类别，防止 AI 发明历史案例。
✓ 有历史依据: 客户集中度风险 （COMP-042，2022_储能_工商业.md） ✓ 有历史依据: Pre-A毛利率普遍低于25% （COMP-037，行业研究） ⚠ AI推断: BMS壁垒的技术可持续性 （无直接历史依据） ⚠ AI推断: 创始人背景的团队可比性 （合理推断，需核实）
步骤 07 代号还原 + 存档 ~30 秒 全自动
代号→真实名称的还原只在这一步发生。存入 Supabase 的是代号版本（保护隐私），输出给投资经理的是可读版本。
// 存库（代号版，长期保存） Supabase.projects: { company_alias: "COMP-089", summary: [代号版报告] } // 输出（还原版，给人阅读） COMP-089 → 极光储能科技（杭州）有限公司 PERSON-034 → 王建明
步骤 08 飞书推送 + @通知 ~1 分钟 人工接手
摘要卡片推送到飞书群，完整报告自动创建飞书文档，@相关分析师。人工工作从这里开始：判断、访谈、决策。

数据安全

脱敏不是安全感，是架构约束

很多系统把"加了权限控制"当作安全保障。这套系统的安全策略是：让敏感数据从物理上不存在于外部服务的调用链中。

🏷

实体代号化

公司名、创始人、机构名称——所有可识别实体在进入 AI 调用链前替换为代号。代号由 SHA-256 生成，不可逆推，不是顺序编号（COMP-001、002……），无法猜测。

极光储能科技（杭州）有限公司 → COMP-089
王建明 → PERSON-034
💰

金额区间化

精确融资金额是高度敏感信息。3000万元 → [千万级]，不向 AI 暴露精确数字。区间足够让 AI 理解项目阶段，又不足以定位具体项目。

融资 3000 万 Pre-A → [千万级] Pre-A
估值 1.5 亿 → [亿元级]
🗂

赛道泛化

细分赛道描述太具体会间接暴露公司身份。"宁德时代供应链 · 固态电池 BMS"即使不提公司名也能被识别。统一泛化到二级行业分类。
